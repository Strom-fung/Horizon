x86 Emulator Team Fixed Terrible Code During Emulation⭐️ 8.0/10

The x86 emulator team at Microsoft encountered a program that allocated 64KB of memory on the stack using an extremely inefficient loop that initialized memory one byte at a time, and they patched the emulator to replace that loop with a fast memory initialization routine. This story illustrates the extreme lengths compatibility layers go to for legacy software, and highlights how emulation can sometimes fix bugs in the original code, a practice that continues today with Proton and Wine. The program used a loop like ‘for (i=0; i<65536; i++) stack[i]=0;’ which was extremely slow; the emulator team detected this pattern and replaced it with a fast ‘rep stosb’ instruction during emulation, without modifying the original binary.

Iroh 1.0: Peer-to-Peer Networking Library Released⭐️ 8.0/10

Iroh 1.0, a stable release of the Rust-based peer-to-peer networking library, is now available after 65 pre-release versions. It enables app instances to connect directly using cryptographic keys instead of IP addresses, with built-in support for IPv4, IPv6, and relay transports. Iroh simplifies peer-to-peer connectivity for application developers, removing the need for user accounts or complex network configuration. This milestone marks a significant step toward decentralized networking, with over 200 million endpoints created on public relays in the last 30 days. The library supports custom transport implementations, allowing developers to add protocols like WebRTC or BLE without bloating the core codebase. It uses cryptographic key pairs (asymmetric keys) for endpoint identity, and relays are used to establish connections when direct paths are unavailable.

AMD quietly removes memory encryption from consumer CPUs⭐️ 8.0/10

AMD has silently removed Transparent Secure Memory Encryption (TSME) from its consumer Ryzen CPUs, a feature that was previously available for nearly a decade. The removal was discovered by users who noticed the feature no longer appears in their system’s security capabilities. This move exposes millions of consumer Ryzen users to cold boot attacks and other physical memory attacks, undermining hardware security for personal and enterprise devices. The lack of transparency erodes user trust and raises concerns about AMD’s commitment to consumer security. TSME encrypts all data in system memory, protecting against physical attackers who might read RAM directly. AMD has stated that TSME is now reserved for its PRO series CPUs, but has not provided a clear explanation for the change or warned users beforehand.

rss · Ars Technica · Jun 15, 17:55

Background: Transparent Secure Memory Encryption (TSME) is a hardware security feature that encrypts the entire contents of system memory, making it resistant to cold boot attacks and other physical exploits. AMD introduced TSME in high-end CPUs around 2016 and later expanded it to consumer Ryzen chips, offering users an extra layer of protection without performance impact. The feature was enabled by default and transparent to the operating system and applications.
